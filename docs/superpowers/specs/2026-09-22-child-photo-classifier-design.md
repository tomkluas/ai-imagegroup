# 儿童照片离线分类软件设计规格

## 1. 项目目标

为 Windows 10/11 早教园区提供一款本地离线桌面软件。老师可在界面中管理约 50 名小朋友及每人 3～5 张参考照片，选择每日约 500 张来自不同手机的待分类照片，软件按照片中出现的小朋友将原图复制到相应姓名目录。一张照片包含多名小朋友时，应分别出现在每位小朋友的结果目录中。

软件优先避免误认和错发照片。清晰且可信的人脸自动分类；不够确定的人脸进入人工确认；远景、严重侧脸、低头、遮挡、后脑勺、脸部过小或无法可靠判断的照片可不分类。软件不修改、移动或删除输入原图。

## 2. 约束与成功标准

- 仅支持 64 位 Windows 10/11。
- 可在 2 核 CPU、8GB 内存、无独立显卡的普通办公电脑运行。
- 无需安装 Python、数据库、CUDA 或其他运行环境。
- 全部识别在本机完成，不上传照片、人脸特征或使用情况。
- 无订阅费、API 调用费或按量费用。
- 支持约 50 名小朋友、每人 3～5 张有效参考照、单次约 500 张照片。
- 输入照片通常为约 3456×4608、2～10MB，但必须兼容不同手机、尺寸、方向和文件大小。
- 在约定的目标电脑和代表性 500 张真实照片上，纯识别阶段不超过 2 分钟。若实测未达到，则性能验收不通过，需要继续优化或由用户重新确认范围；不得以降低自动分类安全门槛换取速度。
- 文件复制耗时与识别耗时分别显示。机械硬盘复制数 GB 原图造成的额外耗时不计入纯识别耗时。

## 3. 首版范围

首版包含：

- 小朋友及参考照片可视化管理；
- 姓名文件夹批量导入；
- 选择待分类文件夹或多张独立图片；
- 选择输出目录和参与本次识别的小朋友；
- 离线人脸检测、识别与多人物照片分类；
- 低可信结果人工确认；
- 分类结果浏览、修正和打开输出目录；
- 本地任务历史、分类报告、参考库备份与恢复；
- 自动硬件检测与动态并发配置；
- 中断、取消和异常退出后的安全恢复。

首版不包含：

- 微信自动发送；
- 自动生成工作描述；
- 云端同步、账号系统或多人同时编辑；
- 视频识别和手机端应用；
- 对后脑勺或完全遮挡人脸进行身份识别；
- 在未经人工复核的情况下承诺 100% 准确。

## 4. 技术路线

### 4.1 技术选型

- Python：业务逻辑和桌面程序开发语言。
- PySide6：Windows 桌面界面。
- OpenCV：图像处理、模型推理与人脸对齐。
- YuNet：轻量级人脸检测模型。
- SFace：人脸特征提取与相似度计算模型。
- SQLite：小朋友、参考照片、任务和分类记录。
- psutil：CPU、内存和可用磁盘信息检测。
- PyInstaller：打包 Windows 可执行程序。

不采用云端人脸 API、生成式大模型、Docker、CUDA 或外部数据库。YuNet 与 SFace 模型随安装包离线提供，并固定版本、记录来源、许可证和文件校验值。

### 4.2 选择理由

YuNet 检测模型轻量，SFace 可直接通过 OpenCV 在 CPU 上运行。该组合的 Python 依赖和 Windows 打包复杂度低于 dlib 路线，并避免部分其他预训练模型权重的商用许可不确定性。识别引擎与界面及任务系统隔离，真实测试若证明效果不足，可替换引擎而不重写整个应用。

## 5. 用户界面与操作流程

应用使用左侧导航，包含“小朋友管理”“新建分类任务”“待人工确认”“分类结果”和“设置”页面。

### 5.1 小朋友管理

- 列表显示姓名、头像和有效参考照数量。
- 支持新增、改名和删除小朋友。
- 支持选择或拖入参考照片，查看和删除已导入照片。
- 支持按下列结构批量导入：

```text
参考照片/
├─ 张小明/
│  ├─ 1.jpg
│  ├─ 2.jpg
│  └─ 3.jpg
└─ 李小红/
   ├─ 正面.jpg
   └─ 侧面.jpg
```

- 子目录名作为小朋友姓名；同名儿童应使用“姓名-班级”或其他园区唯一标识区分。
- 导入时检查是否检测到主要人脸、是否存在多张显著人脸、人脸尺寸和基本质量是否合格。
- 多人参考照、无脸、脸部过小或质量不足的照片不进入有效参考库，并说明原因。
- 每人少于 3 张有效参考照时显示提示，允许继续使用但不保证同等效果。
- 删除小朋友或参考照需要二次确认。删除应用内副本和对应特征，不删除用户最初选择的源文件。
- 人工确认结果仅用于当前任务；只有用户主动选择“同时加入参考照片”时才进入参考库。

### 5.2 新建分类任务

- 支持选择一个待分类文件夹，或选择多张独立图片。
- 支持 JPG、JPEG、PNG、BMP 和 WebP；格式解码失败时记入异常列表。
- 显示待处理缩略图、照片数量、估算数据量和重复文件提示。
- 选择输出目录并填写任务名称，默认名称为当前日期和时间。
- 开始前显示全部候选小朋友，允许临时取消勾选本次不参与识别的人。
- 开始前检查输出目录写权限和可用空间。
- 运行中显示总数、完成数、识别耗时、复制耗时、当前速度和预计剩余时间。
- 支持取消；取消后保留已落盘的任务记录和已完成结果，可继续查看。

### 5.3 待人工确认

- 展示整张照片并框出待确认人脸。
- 给出相似度最高的三个小朋友候选。
- 支持选择候选姓名、搜索其他姓名、标记“不是这些人”或暂时跳过。
- 确认一个待定人脸不影响同一照片中已经自动识别或仍待确认的其他人脸。
- 人工确认后将整张原图加入对应小朋友的分类结果。

### 5.4 分类结果

- 按历史任务浏览结果。
- 左侧显示小朋友和照片数量，右侧按需加载缩略图。
- 点击缩略图可查看原图，并查看该照片识别出的全部小朋友。
- 支持修改错误分类、从某位小朋友结果中移除照片和补充遗漏分类。
- 修改只调整任务记录和输出副本，不修改输入原图。
- 支持查看未识别照片、异常照片和人工确认状态。
- 支持打开 Windows 输出文件夹和导出 CSV 分类报告。

## 6. 识别与判定流程

### 6.1 参考库建立

1. 按 EXIF 信息修正显示与分析方向。
2. 检测参考照片中的人脸和关键点。
3. 检查主要人脸数量、脸部尺寸和基础质量。
4. 对齐有效人脸并提取 SFace 特征。
5. 每张有效参考照保留独立特征，不将 3～5 张照片简单合并成单个平均值。
6. 缓存特征、模型版本和源照片指纹。参考照片未变化时不重复提取。

### 6.2 待分类照片处理

1. 扫描输入，建立照片清单并排除任务内重复项。
2. 读取 EXIF 方向，优先获取内嵌缩略图；不可用时缩小解码供分析。
3. 将分析图长边控制在约 960～1280 像素。最终尺寸由真实样本的速度与召回率测试确定。
4. YuNet 检测所有满足最低尺寸和质量要求的人脸。
5. 对齐每张有效人脸，并提取 SFace 特征。
6. 将特征与本次启用的所有参考特征比较。
7. 为每张脸计算最佳姓名、最佳相似度、第二名相似度和两者差距。
8. 根据阈值、名次差距与人脸质量将结果分为自动分类、人工确认和未识别。
9. 汇总照片中的全部已识别姓名。同一孩子即使在同一照片中被检测多次，也只产生一份该孩子的结果副本。
10. 识别记录落盘后复制原文件到结果目录。

### 6.3 保守判定原则

- 高于自动分类阈值且与第二名差距足够大，才允许自动分类。
- 有合理候选但达不到自动门槛时进入人工确认。
- 无脸、脸太小、质量过低、相似度不足或候选过于接近时不自动分类。
- 不使用公开数据集的通用阈值直接作为最终生产阈值。阈值必须用园区未参与参考库的真实照片校准。
- 优先降低自动误认率，允许将较多困难照片留给人工确认或未识别。

## 7. 输出规则

任务默认输出结构：

```text
用户选择的输出目录/
└─ 2026-09-22_任务名称/
   ├─ 张小明/
   ├─ 李小红/
   ├─ 待人工确认/
   └─ 分类报告.csv
```

- 一张照片识别到多位小朋友时，向每位小朋友目录各复制一份原图。
- 不移动、不修改和不删除输入原图。
- 同名文件使用稳定的序号或源文件指纹后缀避免覆盖。
- 同一照片不会在同一小朋友目录重复复制。
- 输出占用空间可能因多人照片而大于输入数据量；开始前给出估算，完成后显示实际占用。
- 界面修正结果时，以任务记录为真值，并用可恢复的文件操作同步输出目录。

## 8. 性能与资源管理

### 8.1 自动硬件检测

首次运行检测：

- CPU 逻辑核心数和可用核心数；
- 总内存和当前可用内存；
- 可获取时的磁盘类型和剩余空间；
- OpenCV 模型加载和推理是否正常；
- 短时图片解码与推理基准。

检测结果保存到本地配置。每次任务开始前重新检查当前可用内存并允许临时下调并发。硬件信息获取失败时，按 2 核、8GB、2 个工作线程的保守配置运行。

### 8.2 并发策略

- 图片读取/解码、检测识别和文件复制采用有界流水线。
- 解码线程通常为 2～4 个，具体值由自动检测和短时基准决定。
- 检测/识别并发必须考虑 OpenCV 内部线程，避免线程叠加导致争抢。
- 文件复制并发按磁盘表现限制，机械硬盘采用较低并发。
- 队列大小和缩略图缓存按可用内存动态设置，并为 Windows 和其他应用预留内存。
- 设置页提供“节能、均衡、高速”三个档位，默认“均衡”，并提供“重新检测硬件”按钮。首版不向普通用户暴露底层线程参数。

### 8.3 缓存与增量处理

- 参考照片按内容指纹、修改状态和模型版本缓存特征。
- 同一任务内使用内容指纹排除重复文件。
- 已识别且内容、模型和参考库版本均未变化的照片可复用结果。
- 缩略图按需生成和加载，禁止在结果页一次解码全部原图。
- 日志分别记录扫描、解码、检测、识别和复制耗时，以便定位瓶颈。

## 9. 数据存储与模块边界

### 9.1 主要模块

- `ui`：页面、对话框、缩略图网格和进度展示。
- `people`：小朋友、参考照导入、校验和生命周期管理。
- `recognition`：检测、对齐、特征提取、相似度与判定策略。
- `tasks`：任务状态机、队列、暂停/取消、恢复和进度事件。
- `storage`：SQLite 仓储、迁移、文件路径和事务。
- `output`：文件复制、冲突命名、结果修正和报告导出。
- `hardware`：设备检测、基准测试和运行配置。

识别引擎通过稳定接口接收分析图和参考特征，返回人脸框、质量、候选及分流结果。界面不直接操作模型或 SQLite，文件复制不参与识别判定。

### 9.2 应用数据

应用数据默认保存在当前 Windows 用户的应用数据目录：

- `data.db`：小朋友、参考照片、任务、检测人脸和分类关系；
- `models/`：固定版本的离线模型；
- `reference/`：由应用管理的参考照副本；
- `features/`：参考特征缓存；
- `thumbnails/`：可重建的缩略图缓存；
- `logs/`：不包含完整人脸图像的诊断日志；
- `config/`：硬件检测、档位和用户偏好。

数据库变更使用版本化迁移。任务状态、识别记录和输出操作采用事务或明确的可恢复状态，防止异常退出后数据库与文件目录永久不一致。

## 10. 异常与恢复

- 损坏或无法解码的图片记入异常列表，任务继续。
- 输出目录不可写时禁止开始。
- 开始前估算空间；运行中空间不足时停止复制并保留识别记录，用户释放空间后可继续。
- 模型缺失、校验失败或无法加载时禁止开始并提示重新安装。
- 取消任务时停止新增工作，完成正在执行的最小安全单元，保存当前状态。
- 异常退出后重新打开，允许继续未完成任务或从已有识别记录重新生成输出。
- 参考库发生变化时仅重新处理新增、替换或删除的参考照片，并提升参考库版本。
- 小朋友姓名包含 Windows 非法文件名字符时在保存前提示修正。
- 删除、改名或修正分类使用事务及可恢复文件操作；失败时不丢失原始输入和已有任务记录。

## 11. 隐私与安全

- 程序不要求登录，不连接云端，不包含遥测或统计上传。
- 照片、人脸特征、任务和日志只存本机。
- 参考照片与特征属于敏感生物信息，界面应明确提示园方妥善控制 Windows 账户、电脑和备份介质权限。
- 提供“备份参考库”“恢复参考库”和“彻底删除小朋友资料”。彻底删除仅作用于应用管理的副本、特征和记录，不删除用户原始来源照片。
- 日志仅保存路径、状态、耗时和错误信息，不嵌入完整图片或人脸裁剪。
- 发布包记录第三方依赖、模型来源和许可证。
- 园方负责取得监护人授权并建立照片保存、发送和删除制度。

## 12. 测试与验收

### 12.1 功能测试

- 管理至少 50 名小朋友，每人 3～5 张有效参考照。
- 批量导入与界面增删改均保持数据库、参考副本和特征一致。
- 文件夹和多选图片两种输入方式正常。
- 单人、多人物、无人脸、重复、损坏和不同方向图片得到预期状态。
- 多人物照片正确复制到每个相关孩子目录且无同目录重复。
- 人工确认、跳过、修正和结果补充分流正确。
- 取消和异常退出后可恢复，且不损坏已完成记录。
- 中文路径、中文姓名和长路径场景经过测试。

### 12.2 准确率测试

- 从未参与参考库的真实园区照片建立测试集，并人工标注可辨认的人脸身份。
- 分别统计自动分类准确率、自动误认率、人工确认比例和未识别比例。
- 核心验收原则是自动结果中极少出现错认；困难样本进入人工确认或未识别是允许行为。
- 参考照片和测试照片严格分离，禁止用同一照片同时做参考和准确率验证。
- 根据测试结果校准自动阈值、人工确认阈值、第一/第二名差距和最小脸尺寸。

### 12.3 性能测试

- 使用目标 2 核、8GB、无独显办公电脑和约 500 张、3456×4608、2～10MB 的真实照片。
- 分别记录扫描、解码、检测、识别、数据库写入和原图复制耗时。
- 在约定的目标电脑和代表性 500 张真实照片上，纯识别阶段必须不超过 2 分钟；模型预热、首次参考库建立和原图复制分别计时，不混入纯识别指标。
- 性能目标若未达到，先根据分段数据优化解码、分析分辨率、OpenCV 线程和流水线，不以降低自动分类安全门槛换取速度。
- 测试节能、均衡、高速档位和硬件检测失败的默认配置。
- 运行时内存不能持续失控增长，Windows 应保持可交互。

### 12.4 安装与兼容测试

- 在未安装 Python 的干净 Windows 10 和 Windows 11 64 位环境测试。
- 提供安装版；便携压缩版可作为辅助交付。
- 安装、首次模型校验、参考库建立、升级和卸载均需测试。
- 卸载默认不静默删除参考库与任务数据；用户主动选择清除时必须明确提示。

## 13. 交付结果

- Windows 64 位安装程序和可选便携版；
- 完整 Python 源代码；
- 固定并校验的离线模型；
- 第三方依赖与许可证清单；
- 简明中文使用说明；
- 真实目标电脑上的准确率与性能测试报告；
- 参考库备份、恢复和数据删除说明。

本规格获最终批准后，下一阶段只制定详细实施计划，不在规格审批阶段开始产品代码实现。
